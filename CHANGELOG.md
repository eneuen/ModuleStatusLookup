# Changelog

All notable changes to this module are listed here. Versions follow [Semantic Versioning](https://semver.org/).

## [Unreleased]

Added:

- **The lookup line's number.** On install the module takes internal number 2300, or the first free number up to 2399, and registers it in the PBX's extensions as a module number. It then appears as "Module: Status Lookup (2300)" in the PBX's destination pickers (incoming routes, IVR menus) while the module is enabled, and is hidden while it is disabled. 2300 is used because the PBX numbers its own IVR menus, queues and applications from 2200100 up, so 2200 would be a prefix of them. A reinstall that keeps settings keeps the number; an uninstall without kept settings releases it, unless a route still points at it.
- **The module page** (administrators only) shows the lookup line's number.
- **The call flow.** A caller who reaches the line hears a welcome, types an ID and #, and hears its status: one recorded sentence, optionally followed by the ID read back or a date (weekday, month and day, in the PBX's language). After the status the line either says goodbye, offers "1 to hear it again, 0 to speak to someone", or sends the caller straight to the status's own destination. 0 at the ID prompt reaches the operator destination; an invalid entry, an unknown ID or an expired record costs a try, and after the last try (3 by default) the caller goes to the too-many-tries destination. A status whose destination no longer exists, or that can't be played, sends the caller to the fault destination; if that is gone too, they hear an apology. Until the line is switched on and has an operator destination, it apologises and hangs up.
  - The dialplan plays the prompts and collects the digits; a short AGI script runs once per try, looks the ID up (digits within the configured length only, one indexed read, bound parameters) and returns the result in channel variables. PHP is in the call for milliseconds, and a caller who hangs up leaves no PHP process behind.
  - The line behaves like the PBX's own IVR menus: it has its own row in the call history, tells the incoming route the call was answered (so the caller doesn't fall through to the route's next rule or default action), and takes transfers from phones. Its own 2-minute limit replaces the incoming route's ring timeout, which the PBX would otherwise apply to it, and is cleared before the caller is sent on, so a conversation is never cut short. The lookup part of a call isn't recorded: callers type IDs there.
  - IDs are digits, kept as text, so leading zeros count (`00451` and `451` are different records), and are at least 2 digits long, so 0 always means "speak to someone".
- **Miss limits** against guessing: a caller number (withheld numbers share one) that missed 10 lookups in the last hour, or all callers together missing 200, is sent straight to the operator destination. Test calls don't count; 0 turns a limit off.
- **Built-in prompts** (welcome, enter ID, enter PIN, invalid, not found, repeat menu, goodbye, transfer, fault) are the default for every prompt, played in the PBX's language, or in English for languages the module has no recordings for. The recordings themselves are still to come.
- **Call log.** Every call is logged once, also when the caller hangs up in the middle: a hangup handler, or the line itself just before it sends the caller on, hands the call to the module's worker, which validates it again and stores how it ended, the tries and misses, the last ID entered, the status and where the caller was sent. Daily counts per outcome, without phone numbers, are kept alongside.
- **Protection of what the line uses:** the PBX refuses to delete a sound file the line plays, or an extension, queue or IVR menu it sends callers to.
